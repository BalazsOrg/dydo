## Why

Agents may not delete remote branches or worktrees, because a delete can destroy unmerged work. So Balazs is asked to run wizards to delete them, again and again, and he admits he rarely takes a second look at what's being deleted. In his words: "I don't think this should be my job … moving this to agents and making sure it is failsafe is actually probably safer than what we have today." Merged work is already safe to delete. Unmerged work is the risk.

## What it does

A dydo command that deletes a branch or worktree by first preserving it in a temporary archive, so a wrong delete loses nothing.

* **Archive first, then delete.** The branch's commits and, for a worktree, every uncommitted and untracked file go into the archive. Uncommitted files are **copied in as they are**, with no commit made. Then the branch or worktree is deleted, from GitHub too.
* **The archive lives on this machine.** Balazs's reasoning: losing work would need two failures, a wrong delete *and* a dead disk, and the dead disk is the far bigger problem anyway. A remote branch may never have been fetched here, so the command fetches it before archiving. An empty archive is a failure, not a success.
* **Kept 30 calendar days.** No background job. Archives older than 30 days are purged **only when the archive/delete command itself runs**. Nothing is deleted while nobody runs it.
* **A restore command** brings a branch or worktree back from the archive.
* Agents use this command freely. Plain `git branch -D`, `git push --delete` and worktree removal stay blocked for agents.

### Command surface

Proposed grammar:

* `dydo archive branch <name> [--remote <remote>] [--dry-run]`: archive and delete that local branch and its same-name branch on the selected remote.
* `dydo archive worktree <path> [--remote <remote>] [--dry-run]`: archive and remove one registered linked worktree, its attached local branch, and that branch on the selected remote. A detached HEAD still gets a commit archive but has no named remote branch to delete.
* `dydo archive list`: repository-local entries, ID, original target, creation/expiry, completeness and delete outcome.
* `dydo archive restore <id> [--branch <new-name>] [--path <new-path>] [--remote]`: restore locally by default without overwriting refs/directories. Explicit --remote recreates only an absent original same-name remote ref using a create-only lease.

`archive` is the delete verb: no archive-only mode or raw-delete fallback. The upstream may choose only the remote, never the ref to delete. Delete only refs/heads/<the named local branch> on that remote; a differently named upstream is reported as kept. Otherwise select origin when configured; require an explicit remote when ambiguous. Apply eligibility checks independently to the local and same-name remote refs. Explicit `--remote` selects the same-name remote branch. Local repositories with no remote work locally. Existing remote lookup/fetch failure is fatal; an absent branch is distinguished from network/auth failure. Before any remote/local destructive step for a remote-backed target, gh must establish that its same-name remote branch is neither feature/\* nor an open PR head or base. Failed, offline or incomplete lookup refuses remote deletion and keeps the local target. Unsupported remote hosts cannot silently bypass the check. Real local-bare transport tests inject the GitHub query seam. Ref names and argv are validated; no shell interpolation. Default branches, the main worktree, current/in-use/locked worktrees, and branches checked out elsewhere are refused. T3-made targets are in scope under the lifecycle contract below, superseding the blanket \~/.t3/worktrees exclusion for this command. A dry run lists intent but neither fetches, creates an archive, deletes nor purges.

### Local archive and contents

Use `<absolute git common dir>/dydo/safe-delete-archive/<UTC timestamp>-<random ID>/`, shared by all linked worktrees and separate from the existing clean archive. On this machine the root is `/home/balazs/Desktop/Projects/DynaDocs/.git/dydo/safe-delete-archive/`. No size-based eviction. Estimate archive bytes plus independent-proof scratch, including ignored files; dry-run prints both and their sum. For every affected volume, before allocations require remaining available space after archive and proof to be at least max(archive.reserveBytes, archive.reservePercent × volume total / 100). These dydo.json keys default to 5368709120 bytes (5 GiB) and 10 percent. Validate reserveBytes as nonnegative integral bytes and reservePercent as finite 0–100; invalid configuration refuses. Refusal prints both estimates, available/total space, both settings and the computed reserve. Do not credit speculative compression or purge; recheck before allocations and handle ENOSPC without deleting targets. Preflight does not lock out unrelated volume writers. Do not follow symlinks/junctions in archive ancestors or entries; refuse unsafe paths.

Each entry has versioned `manifest.json`, a self-contained `commits.bundle`, and for a worktree `files/` plus captured index/HEAD metadata. The manifest records original repository/worktree/branch/remote identities (redact URL userinfo and credential-bearing query values), every captured tip OID, timestamps, files/directories/link metadata, hashes, completion and deletion progress. Write through a unique incomplete staging entry and publish completeness only after verification.

Fetch the selected remote branch into an isolated temporary ref before archiving, even if it was never fetched here. Preserve all reachable commit history of the local tip, fetched remote tip and detached worktree HEAD, including divergent tips, with no prerequisite objects borrowed from the source repository. Include every commit named by the target branch reflog, worktree HEAD reflog and per-worktree refs (worktree, bisect and rewritten refs), retain their log/ref metadata, and list separately recoverable tips. Refuse in-progress merge, rebase, sequencer/cherry-pick, am or bisect state before any deletion. Never make a commit. Shallow history, missing objects, LFS/gitlink dependencies or unsupported filesystem objects must not be silently treated as complete: preserve their required data or refuse before any delete.

For a worktree copy its complete file state as it stands, including binary, staged/unstaged, untracked and ignored files; record tracked deletions, empty directories, executable bits and link targets. Do not traverse links outside the tree. Git administrative metadata is preserved separately rather than copied as a live repository link; preserve the index and every object it references (all conflict stages and intent-to-add metadata), including staged-only blobs absent from HEAD and the working files, so staged and unstaged states remain distinguishable. Keep these blobs in a separately verified self-contained object pack or equivalent; a copied index alone is insufficient. Initialized nested repositories/submodules or special files require complete independent preservation; otherwise refuse with an actionable reason. No build-output omission or archive size cap may cause a delete to discard a file.

### Archive-before-delete proof

A nonempty verified commit archive is mandatory even for a clean worktree or fully merged branch. No refs, empty/missing/truncated bundle, missing file, unreadable source, copy/hash mismatch, unsupported state or failed verification means nonzero exit with the original target retained. Verify the bundle and index object pack by importing into a fresh empty scratch repository and checking every recorded tip, reachable object and referenced index blob. Both commit verification and worktree/index reconstruction run without access to the source Git object store: no alternates, shared object directory or inherited Git environment. Compare reconstructed files, deletions, links, staged and unstaged status to the snapshot. Required regression: partially stage one version, change the working file again, archive/delete, run git gc --prune=now in the source, then restore and recover both versions. This proves the restore route before deletion.

Serialize archive/delete/restore/purge operations per common repository. Recheck refs and the source snapshot before destructive steps; detected changes abort. Local ref deletion is compare-and-swap against the captured OID. Remote deletion uses an explicit expected-OID lease; a remote that moved after fetching stays. For a worktree remove the remote ref first, then the verified worktree, then its local branch by compare-and-swap; never delete a branch while it is still checked out. A remote refusal leaves the local target. Every destructive step requires a published verified entry and records its result. If a later step fails, retain the archive, report exactly what remains and return nonzero; never claim atomic rollback or total success. Retry cannot overwrite newer work or discard the last recoverable copy.

Restore validates the manifest and hashes first, then reconstructs into a new path/ref. It imports the archived objects without depending on surviving source refs, recreates the working files and index, and verifies the outcome. Divergent captured tips remain separately recoverable and are listed explicitly. Existing refs/paths, corrupt data, traversal paths, linked archive containers or unsupported metadata fail without overwriting user work. Keep the archive after restore and on any failure.
